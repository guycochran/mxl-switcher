01 / THE OUTCOME

A decision package, not an endless prototype.

Every pilot starts with the decision your team needs to make and ends with enough evidence to make it. The working demo matters; the repeatable evidence and honest boundary matter more.

01

Success contract

One workflow, named inputs and outputs, observable pass/fail criteria, resource limits and an agreed stop condition.

02

Working vertical slice

A real signal path using the minimum useful set of contribution, MXL processing, operator control and delivery functions.

03

Operator surface

A role-appropriate control or health view so the proof looks and behaves like broadcast equipment—not a collection of terminal windows.

04

Evidence package

Measured cadence, drops, CPU, memory and recovery behavior, plus screenshots, reproducible steps and known limitations.

05

Go / adapt / stop recommendation

A concise architecture recommendation showing what belongs in MXL, what stays at the edge and what should not be built yet.

06

Handoff

Public-safe documentation and a private operator handoff that another engineer can follow without depending on the original lab.

02 / STARTING PROFILE

Compress at the edge.
Share in the core.

The recommended first deployment is a single production host with enough CPU and RAM for the validated workload. SRT, NDI, SDI or ZoomISO can terminate at adapters; MXL carries timestamped media between in-host functions; a purpose-built edge encodes the finished output.

03 / FIT CHECK

Useful now—and explicit about what is not ready.

Good pilot fit

  • Build a credible MXL production demo for customers or internal stakeholders.
  • Integrate one vendor function or transport into an MXL workflow.
  • Compare a bounded MXL path with an existing NDI or SRT approach.
  • Measure a deployment before funding a larger product effort.

Not the current promise

  • A feature-for-feature replacement for vMix, OBS, AMPP or a production switcher.
  • An unattended 24/7 appliance with a full broadcast SLA.
  • A universal claim that MXL always outperforms every NDI configuration.
  • A finished TAMS editing, trimming and replay product.

04 / WHY THIS LAB

The failures are part of the deliverable.

The reference work has already exposed cadence errors, stale flows, audio-boundary problems, cloud sizing limits and operator-recovery gaps. The pilot converts that experience into acceptance gates instead of rediscovering it on your budget.

BOUND THE CLAIM

Measure the exact path

CPU and reliability statements are tied to disclosed formats, readers, host classes and test conditions.

REHEARSE THE INSTALL

Fresh-host workflows

Deployment is treated as part of the product. A result that only works on the original lab is not accepted.

OPERATE, DON'T JUST RENDER

Health and recovery

The proof includes visible state, safe controls and recovery behavior—not only a successful frame grab.

KEEP THE GATE

No automatic expansion

The next feature or topology is funded only after the current pilot earns a reason to continue.
