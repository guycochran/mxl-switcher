# Domain and identity strategy

## Recommendation

Use the public-facing title **Switcher Lab for MXL™** while written trademark
permission is pending. Treat `mxlswitcher.com` as a held domain, not as proof
that the project owns or represents MXL.

If LF Projects grants written permission for the domain, use this structure:

- `mxlswitcher.com` — permanent informational front door (this site)
- `demo.mxlswitcher.com` — the live, operator-driven control surface
- `docs.mxlswitcher.com` — optional future documentation, or keep GitHub as docs
- GitHub — canonical source, issues, releases, governance and contribution

Separating the informational site from the live demo keeps the project's public
identity available when Azure is deallocated, the demo is under maintenance, or
a live endpoint changes.

If permission is declined or remains unresolved, publish the same site at a
neutral domain and use **Switcher Lab for MXL™** only as a compatibility phrase.
Do not acquire additional domains containing `MXL` or `DMF-MXL` unless the mark
owner asks the project to hold or transfer them.

## Positioning rules

1. Lead with “independent, open-source field project,” not “official,”
   “reference,” or “the MXL switcher.”
2. On first prominent use, write **Media eXchange Layer (MXL)™**.
3. Use a project identity more prominently than the MXL mark.
4. Do not use the official MXL logo without written permission.
5. Link to the official SDK, EBU DMF work, AMWA BCP-007-03, CBC's media
   functions and easy-mxl.
6. Keep the non-affiliation notice visible in the header and complete in the
   footer.
7. Describe measurements as this project's results, not as guarantees about the
   upstream SDK.
8. Keep runtime status, costs and version numbers dated so the informational
   site remains trustworthy.

## Stewardship

The domain should outlive any one demo VM or personal account. The practical
minimum is:

- documented registrant and renewal owner;
- two trusted administrators with MFA for the registrar and DNS;
- automatic renewal with a shared renewal calendar;
- source and deployment configuration in the public repository;
- a short governance file stating who can approve domain, branding and hosting
  changes; and
- a written promise to transfer the domain to the upstream project if requested
  as part of an approved community home.

## Current trademark constraint

As of September 15, 2026, the LF Projects trademark policy lists **Media
eXchange Layer (MXL)™** among its marks. Its general rules say a mark should not
be used in a domain name or product name and give “&lt;your product name&gt; for
&lt;LF Projects mark&gt;” as an example of compatible-use naming. This is why the
site uses **Switcher Lab for MXL™** and why the custom domain should wait for a
written response.

Policy: <https://lfprojects.org/policies/trademark-policy/>

This document is a project-positioning recommendation, not legal advice.
