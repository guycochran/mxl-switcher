## What you can do without asking

- **Use, modify, and redistribute the code** under Apache-2.0. That's the point.
- **Nominative use** — truthfully refer to the project to describe what your thing works
  with or is built on, for example:
  - "compatible with mxl-switcher"
  - "a skin for mxl-switcher" / "built on the mxl-switcher core"
  - "uses the mxl-switcher `/api/mxl/v1` API"
  - "for MXL" (describing the media exchange layer your product interoperates with)
- Keep the existing copyright, license, and NOTICE text in redistributed copies (required
  by the license anyway).

## Forks and redistributions

If you publish a fork, a modified build, or a hosted service based on this code, **give it
your own name and logo**. Don't present it as the official mxl-switcher, and don't use
the name or logo in a way that suggests endorsement or affiliation. A short line such as
"based on mxl-switcher" in your README or About page is welcome.

## A note on the "MXL" name

"MXL" appears to be the name of the open media exchange layer project developed in the
EBU / Linux Foundation community (the [MXL SDK](https://github.com/dmf-mxl/dmf-mxl)). We
have not confirmed who holds any rights in that name. This project is an independent
implementation and is **not affiliated with or endorsed by** the EBU, the Linux
Foundation, or the MXL project.

**Recommendation:** because "MXL" is someone else's project name, any brand that is
meant to be protected (including this project's own product/brand name, if one is
adopted later) should be **distinctive** rather than built mainly on "MXL". Descriptive
use of "MXL" to say what something works with ("for MXL", "MXL-native") is fine. This is
a recommendation only; nothing is being renamed here.
